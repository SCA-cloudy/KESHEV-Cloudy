# 3일차 기록: 연결과 기록 (STUDENT_DAY3_CONNECTION_LOG)

이 문서는 학생(`student/extension.mjs`를 구현한 사람)이 작성했습니다. `README.md`와 `docs/` 아래의 제공 문서는 고치지 않았습니다. 마무리 과제(마지막 총공세) 3일차 "내 PC의 네트워크 설정, 방화벽 설정, Windows 경고·오류 기록을 읽기만 해서 보여 주고, 못 읽은 것은 `확인 불가`로 보여 줍니다. SDP 서버 연결 상태는 PC 조회와 따로 보여 줍니다"를 어떻게 했는지 적습니다.

확인 표시는 `docs/STUDENT_DAY2_PC_STATUS.md`, `docs/STUDENT_REPRODUCTION_LOG.md`와 같은 기준을 씁니다.

| 표시 | 뜻 |
|---|---|
| **[원문]** | 코드·문서 글을 읽고 비교만 한 것. 실행하지 않았습니다. |
| **[모의]** | 가짜(mock) 응답을 넣어 화면 결과만 점검한 것. 실제 PC 값이 아닙니다. |
| **[실행]** | 학생(저)이 내 Windows PC에서 직접 명령을 치고 브라우저로 눈으로 확인한 것. |
| **[AI 작업 공간]** | AI가 자기 작업 공간(리눅스 컨테이너)에서 진짜 앱 서버로 돌려 본 것. 내 PC가 아니므로 참고만 하고 확인함으로 세지 않습니다. |

- 제공 파일(`public/`, `src/`, 기존 `docs/`)은 고치지 않았습니다.

## 3. 표시 규칙

- **네트워크 연결**: "외부 네트워크 인터페이스 N개 · IPv4 구성 M개"와 함께 "인터넷 접속·유선/무선 여부는 확인하지 않음"을 적습니다. 인터넷에 연결되었다는 뜻이 아닙니다.
- **방화벽 설정**: 프로필(Domain·Private·Public)이 모두 켜져 있으면 그렇게, 꺼진 것이 있으면 "꺼진 프로필: ..."로 보여 줍니다. "읽기만 함 · 설정을 바꾸지 않음 · 안전 판정이 아님"을 함께 적습니다.
- **Windows 경고·오류**: "최근 24시간 System·Application 경고 N건 · 오류 M건"과 "침해·공격 탐지 결과가 아님"을 적습니다. 서버가 읽은 건수가 한도에서 잘렸으면 일부만 센 값이라고 적습니다.
- **SDP 서버**: PC 조회 성공·실패와 섞지 않고 별도 줄로 보여 줍니다. `disconnected`는 `SDP 미연결`, `demo`는 `SDP 미연결 (예제 데이터를 보는 중)`, `connected`는 서버가 연결 모드로 응답했다는 것뿐이며 연결 성공을 확인한 것은 아니라고 적습니다. 모드를 알 수 없으면 미연결로 단정하지 않고 `확인 불가 (서버 연결 모드를 알 수 없음)`으로 보여 줍니다.
- 조회 전, 조회 실패, 지원 없음, 응답 이상일 때는 세 항목 모두 0이나 정상이 아니라 `확인 불가 (이유)`로 보여 주고, "항목 3개 중 실측 n개 · 확인 불가 m개"를 적습니다.

## 4. 개선 한 가지

이 구역의 개선은 **"못 읽은 것을 정상처럼 보이지 않게 하고, SDP 연결 상태와 PC 조회 결과를 서로 섞지 않는 것"** 입니다. 제공 카드는 PC 값만 보여 주고, 서버 연결 모드와 PC 조회가 다른 사실이라는 점은 따로 적지 않습니다. 이 구역은 한 화면에서 둘을 나란히 두되 줄과 문구를 분리해, `SDP 미연결`인데도 PC 값은 읽힐 수 있다는 점이 보이게 했습니다.

## 6. 같은 결과를 다시 만들어 보는 순서

Windows, Node 22~24, 외부 설치(`npm install`) 없음.

1. 저장소를 받고 앱 폴더로 이동합니다.
   ```
   git clone https://github.com/SCA-cloudy/KESHEV-Cloudy.git
   cd KESHEV-Cloudy\on-client
   ```
2. 문법 검사: `npm run check` (오류 없이 끝나야 합니다.)
3. 앱 켜기: `npm start` → 브라우저에서 `http://127.0.0.1:5189`
4. 아래로 내려가 「학생 상태·알림 표시」 안의 「연결과 기록 (읽기만 함)」을 찾습니다. 누르기 전에는 세 항목이 `확인 불가 (아직 조회하지 않음 ...)`이고 SDP 서버는 `SDP 미연결`이어야 합니다.
5. 같은 구역 위의 「PC 값 조회」를 한 번 누릅니다. 네트워크·방화벽·Windows 경고·오류 값이 채워지고 "항목 3개 중 실측 n개"가 나옵니다.
6. 위쪽 제공 카드 「내 PC 상태」의 「내 PC 확인」을 눌러 네트워크·Windows 방화벽·Windows 기록 값이 같은지 비교합니다. 기록 건수는 24시간 범위라 조금 다를 수 있어 시각도 같이 봅니다.
7. 끝내기: 서버 창에서 `Ctrl+C` → `Y`.

## 7. 값이 이상할 때

- 세 항목이 `확인 불가`로 나오면 0이나 정상으로 바뀐 것이 아니라 이번 조회에서 값을 못 읽었다는 뜻입니다. 괄호 안의 이유(조회 실패, 이 PC에서는 지원하지 않음 등)를 봅니다.
- 방화벽·Windows 기록은 Windows에서만 읽습니다. 다른 운영체제에서는 `이 PC에서는 지원하지 않음`으로 나오는 것이 정상 동작입니다.
- Windows 경고·오류 건수가 많아도 침해나 공격이 있었다는 뜻이 아닙니다. 이 앱은 그런 판정을 하지 않습니다.
- `SDP 미연결`은 서버가 연결 어댑터 없이 실행 중이라는 뜻이며, 내 PC 값이 읽히는 것과는 별개입니다.
