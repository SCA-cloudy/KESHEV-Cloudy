# 완성본 시연 순서와 정리 (STUDENT_DEMO_GUIDE)

이 문서는 학생(`student/extension.mjs`를 구현한 사람)이 작성했습니다. 마무리 과제(마지막 총공세) 7일차 요청문("완성본 시연 순서와 정리 문서")에 맞춰, 시연 순서·제공 기능과 내 기능의 구분·한계·근거·다시 해 보는 순서를 한곳에 모았습니다. 새 결과를 만든 문서가 아니라 이미 확인한 것을 정리한 문서이고, 확인하지 않은 것은 된다고 쓰지 않고 미확인으로 남겼습니다. 제공 파일(`README.md`, `public/`, `src/` 등)과 기존 문서, 코드는 고치지 않았습니다.

## 0. 작전과 확인 표시

- 작전: 화면 틀은 관제 대시보드형(맨 위 상태 카드 네 개, 아래 추이와 기록), 포장 형태는 포장 없이 프로젝트 폴더에서 실행(`npm run package-app`은 실행하지 않음). 화면 틀을 "맨 위의 제공 카드 네 개 = 상태 카드, 내 칸 = 추이와 기록"으로 해석했고, 포털이 이 해석을 받아들이는지는 확인하지 못했습니다(`STUDENT_SUBMISSION_NOTE.md` 1절).
- 이 문서의 숫자는 시연할 때마다 달라집니다. 아래 예의 숫자는 2026-11-03 내 PC에서 잰 값이며 `[실행]`으로 표시했습니다. 예시 값(설명용)은 쓰지 않았습니다.

| 표시 | 뜻 |
|---|---|
| **[원문]** | 코드·문서 글을 읽고 비교만 한 것. 실행하지 않았습니다. |
| **[모의]** | 가짜(mock) 응답으로 화면 결과만 점검한 것. 실제 PC 값이 아닙니다. |
| **[시연]** | 예제(demo) 모드처럼 고정된 샘플 자료로 화면을 띄운 것. 실제 연결이 아닙니다. |
| **[실행]** | 학생(저)이 내 Windows PC에서 직접 명령을 치고 브라우저로 확인한 것. 캡처를 남겼습니다. |
| **[AI 작업 공간]** | AI가 자기 작업 공간(리눅스)에서 돌려 본 것. 내 PC가 아니므로 확인으로 세지 않습니다. |

## 2. 시연 순서 (핵심 기능 3가지, 1일차에 정한 순서)

시연 전 준비(한 번): PowerShell에서 `cd "…\KESHEV-Cloudy\on-client"` 후 `npm.cmd start`(CMD에서는 `npm start`), 브라우저에서 `http://127.0.0.1:5189`. 화면 맨 위의 `연결 없음`과 빨간 안내는 정상입니다(회사 시스템에 연결하지 않은 기본 실행).

| 순서 | 핵심 기능 | 하는 일 | 보여야 하는 것 |
|---|---|---|---|
| 0 | 화면 훑기 | 맨 위부터 내려가며 제공 카드(내 PC 상태·현재 로그인·내 기기·내 세션)와 그 아래 「학생 상태·알림 표시」 칸을 가리킴 | 제공 카드가 위, 내 칸이 아래. 내 칸 안에 틀 설명 문장과 「PC 값 조회」 버튼, ① 네 칸이 `확인 불가 (아직 조회하지 않음)` |
| 1 | **내 PC 상태** | 「PC 값 조회」를 한 번 누름 | `조회 성공: 잰 시각 … · 핵심 항목(CPU·메모리·디스크) 3개 중 실측 3개`. ① 카드 네 개에 잰 시각(한국 시간)과 `[실제 측정]`, 방화벽은 `Domain·Private·Public 모두 켜짐 (읽기만 함 · 설정을 바꾸지 않음 · 안전 판정이 아님)`. 첫 조회라 `직전 조회가 없어 비교할 수 없음` |
| 2 | **최근 보안 기록** | 아래 ② 최근 기록을 보여 줌. 「보안 기록」 탭은 제공 화면 그대로임을 말함 | 조회한 줄 하나(시각·CPU·메모리 사용률·디스크 여유)와 `Windows 경고·오류: 최근 24시간 System·Application 경고 N건 · 오류 N건 (침해·공격 탐지 결과가 아님)`. 「보안 기록」 탭은 연결이 없어 비어 있음 |
| 3 | **변화 그래프** | 3초쯤 뒤 「다시 조회」를 한 번 더 누름 | ①에 `직전 대비 …`, ②에 `직전 조회와 비교: CPU … · 메모리 사용률 … · 디스크 여유 …`, ③에 막대 두 줄. 화면에 보이는 두 숫자를 직접 빼서 같은지 보여 줌 |
| 4 | 실패 안내(선택) | 서버 창에서 `Ctrl+C` → `y`로 끄고, 브라우저는 새로고침하지 않은 채 「다시 조회」를 누름. 다시 `npm.cmd start`로 켜고 「다시 조회」를 누름 | 빨간 상자 `앱 서버에 연결하지 못했습니다`, 무엇이 안 됐나, 다음에 할 일, `아래 최근 기록은 이전에 성공한 조회입니다. 이번 값이 아닙니다.`, ① 카드 `확인 불가 (앱 서버에 연결하지 못했습니다)`. 복구하면 기록이 이어짐 |

2026-11-03 내 PC에서 잰 값의 예 [실행]: 12:48:39 → 12:48:54 조회에서 CPU 24.7% → 13.3%는 `-11.4%p`, 메모리 40.7% → 40.7%는 `±0.0%p`, 디스크 77.6 GB는 `±0.0 GB`. 다른 날 다른 PC에서는 숫자가 다릅니다.

연습 기록(2026-11-03 오후 2:56~2:58, 원래 작업 폴더, 최종 코드, `npm.cmd start` 직후부터 끊지 않고 이어서) [실행]: 순서 0(화면 훑기) → 1(「PC 값 조회」: 2:57:43, CPU 19.6% · 메모리 50.2% · 디스크 77.1 GB, 네트워크 인터페이스 3개·IPv4 구성 3개, 방화벽 `Domain·Private·Public 모두 켜짐`, Windows 경고 25건·오류 10건) → 2(왼쪽 메뉴 「보안 기록」 탭: 제공 「접속·XDR 기록」이 `기존 서버·에이전트의 연결을 확인할 수 없습니다`, 내 「학생 구현 표시」가 `기록을 불러오지 못했습니다`, AI 사건 설명이 `보안 기록에서 기록을 먼저 고르세요.`로 모두 비어 있음) → 「보호 현황」으로 돌아와 3(「다시 조회」: 2:58:17, CPU 19.6% → 23.3%는 `+3.7%p`, 메모리 50.2% → 50.2%는 `±0.0%p`, 디스크 77.1 GB는 `±0.0 GB`, ② 기록과 ③ 막대가 두 줄). 탭을 옮겼다 돌아와도 첫 조회 기록이 남아 있었습니다(새로고침하지 않은 경우). 순서 4(서버를 끄고 복구)는 이 연습에서 하지 않았고, 따로 최종 코드로 확인했습니다(4절). 이 연습은 같은 내 PC에서 혼자 한 것이며 다른 사람 앞에서 시연한 것은 아닙니다.

## 3. 아직 안 되거나 `확인 불가`로 남은 한계

| 한계 | 상태 |
|---|---|
| 실제 SDP 연결 | 하지 않음. 실제 연결에는 `--sdp-host-config`와 개인 인증 파일이 필요한데 이 PC에서는 쓰지 않았습니다. 기본 실행은 `연결 없음`이고 22단계는 이 상태로 통과했습니다. 로그인·기기·세션·「보안 기록」 탭·알림이 실제 연결에서 어떻게 보이는지는 확인하지 못했습니다 |
| 「최근 보안 기록」의 뜻 | 연결이 없어서 제공 「보안 기록」 탭은 비어 있습니다. 내 ② 최근 기록은 "내가 조회한 값의 기록과 Windows 경고·오류 건수"이고, 침해·공격 탐지 결과가 아닙니다. 이 해석이 요구와 맞는지는 확인하지 못했습니다 |
| 화면 틀 해석 | 내 카드는 페이지 맨 위가 아니라 제공 카드 아래에 있습니다(위치는 제공 파일 `public/index.html`이 정함) |
| 예제(demo) 모드 화면 | 코드로 안내 문구를 읽었을 뿐 내 PC에서 화면으로 보지 않았습니다(미확인) |
| "읽는 중" 화면 | 최종 코드로 내 PC에서 보지 않았습니다(미확인) |
| 키보드(`Tab`·`Enter`) | 6일차 중간 코드로만 [실행]. 최종 코드로는 다시 하지 않았습니다 |
| 작업 관리자와 값 대조 | 화면에 `대조:` 안내를 붙였지만 최종 코드로 맞춰 본 기록이 없습니다. CPU는 순간값이라 같을 이유가 없습니다 |
| 일부 항목만 못 읽은 화면, 방화벽 미지원 | 내 PC에서는 모두 읽혀 실제로 보지 못했습니다. 가짜 응답으로만 확인([모의]/[AI 작업 공간]) |
| 측정 시각이 60초보다 오래되거나 미래인 화면 | 가짜 응답으로만 확인([AI 작업 공간]) |
| 알림이 배열이 아닐 때 | `확인 불가`로 바꾼 코드를 읽어 확인했을 뿐 실행하지 못했습니다. 알림 안에 비어 있는(`null`) 항목과 필터 `전체`는 이전 단계 코드의 한계로 고치지 않았습니다 |
| 네트워크 | 인터페이스 수와 IPv4 구성 수만 보여 주며, 인터넷 접속·유선/무선 여부는 확인하지 않습니다(화면에도 적음) |
| 단위와 변화 | 단위는 GB로 적었지만 1024 기준(GiB)입니다. 변화는 화면에 보이는 값끼리 빼서 실제로 0.1%p보다 작게 변해도 `±0.0%p`로 보일 수 있습니다 |
| 환경 | 다른 PC, Node 22·23, 인터넷이 끊긴 상태, 좁은 창, 관리자가 아닌 계정(최종 코드)은 확인하지 못했습니다 |

## 5. 같은 결과를 다시 만드는 순서

Windows, Node.js 22~24, Git. 외부 설치(`npm install`)와 포장 명령은 필요 없습니다.

1. PowerShell을 열고 받을 위치로 이동: `cd "$env:USERPROFILE\Desktop"`
2. 받기: `git clone https://github.com/SCA-cloudy/KESHEV-Cloudy.git`
3. 앱 폴더로: `cd KESHEV-Cloudy\on-client`
4. 커밋 확인: `git rev-parse HEAD` (최신 커밋 번호가 나옵니다. 코드 커밋 `6862fadd…` 이후여야 합니다)
5. 코드 검사: `npm.cmd run check` (오류 없이 끝나야 함. `student/extension.mjs`의 `git hash-object`는 `02f70d8d482b3b0fe21747b3eabefcd7b8a9ccd9`)
6. 앱 켜기: `npm.cmd start` → 브라우저에서 `http://127.0.0.1:5189`
7. 위 2절 시연 순서(0 → 1 → 2 → 3, 선택으로 4)를 따라 합니다.
8. 끝내기: 서버 창에서 `Ctrl+C` → `y`

PowerShell에서 `npm`이 `npm.ps1` 때문에 막히면 `npm.cmd`로 입력합니다(CMD에서는 `npm` 그대로). 더 자세한 절차와 막혔을 때 표는 `STUDENT_ONE_PAGE_GUIDE.md`와 `STUDENT_SUBMISSION_NOTE.md` 8절에 있습니다.
