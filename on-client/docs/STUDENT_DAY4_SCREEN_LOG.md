# 4일차 기록: 화면 다듬기 (STUDENT_DAY4_SCREEN_LOG)

이 문서는 학생(`student/extension.mjs`를 구현한 사람)이 작성했습니다. `README.md`와 `docs/` 아래의 제공 문서, `public/`, `src/`는 고치지 않았습니다. 마무리 과제(마지막 총공세) 4일차 "처음 보는 사람도 알아볼 수 있게 화면을 정리하고, '다시 조회' 버튼과 실패했을 때의 오류 화면을 갖춥니다"를 어떻게 했는지 적습니다.

확인 표시는 `docs/STUDENT_DAY2_PC_STATUS.md`, `docs/STUDENT_DAY3_CONNECTION_LOG.md`와 같은 기준을 쓰고, 이번에 하나를 더했습니다.

| 표시 | 뜻 |
|---|---|
| **[원문]** | 코드·문서 글을 읽고 비교만 한 것. 실행하지 않았습니다. |
| **[모의]** | 가짜(mock) 응답을 넣어 화면 결과만 점검한 것. 실제 PC 값이 아닙니다. |
| **[실행]** | 학생(저)이 내 Windows PC에서 직접 명령을 치고 브라우저로 눈으로 확인한 것. |
| **[실행·가짜 응답]** | 내 PC의 실제 앱 화면에서 브라우저 콘솔로 서버 응답만 가짜로 바꿔 넣고 화면을 본 것. 앱 파일과 서버는 바뀌지 않았고, 서버가 실제로 그렇게 응답한 것은 아닙니다. |
| **[AI 작업 공간]** | AI가 자기 작업 공간(리눅스 컨테이너)에서 돌려 본 것. 내 PC가 아니므로 참고만 하고 확인함으로 세지 않습니다. |

- 「보안 기록」 탭은 제공 화면 그대로이고 바꾸지 않았습니다. 핵심 3가지의 "최근 기록"은 내 조회 기록과 Windows 경고·오류 건수입니다.

- 못 읽은 값은 0이나 정상으로 바꾸지 않고 `확인 불가 (이유)`로 보여 줍니다. 정상·안전 판정은 하지 않습니다.

## 3. 고른 개선 한 가지

**"값이 어떻게 변했는지 한눈에 보이게 하고, 조회가 안 됐을 때 무엇을 해야 하는지 알려 주는 것"** 입니다.
- ③ 변화: 최근 5번의 CPU·메모리 사용률을 글자 막대(`█` 사용, `░` 남음, 20칸)로 그립니다. 값 숫자도 같이 적습니다. 내가 조회 버튼을 누른 시점의 값이며 일정한 간격의 그래프가 아니고 새로고침하면 사라진다고 화면에 적었습니다.
- 오류 화면: 원인별로 제목·무엇이 안 됐나·다음에 할 일 3단계를 보여 줍니다. 이전에 성공한 기록이 있으면 "아래 기록은 이전에 성공한 조회입니다. 이번 값이 아닙니다.", 없으면 "아직 성공한 조회가 없어서 아래 기록은 비어 있습니다"라고 적습니다.

오류 화면의 종류:

| 상황 | 화면 제목 |
|---|---|
| 앱 서버에 연결 못 함(`NETWORK_ERROR`) | 앱 서버에 연결하지 못했습니다 |
| 응답 시간 초과(`TIMEOUT`) | 서버가 제때 응답하지 않았습니다 |
| 서버가 읽을 수 없는 내용을 보냄(`INVALID_RESPONSE`) | 서버 응답을 읽을 수 없었습니다 |
| 서버가 오류로 응답 | PC 값을 불러오지 못했습니다 |
| 응답 모양이 약속과 다름 | 응답은 왔지만 형식을 확인하지 못했습니다 |
| 이 앱 판이 허용하지 않음(`NOT_ALLOWED`) | 이 앱 판에서는 학생 코드의 PC 조회를 쓸 수 없습니다 |
| 측정 시각이 60초보다 오래됨 | 측정 시각이 너무 오래된 값입니다 (이 화면은 내 PC에서 만들지 못함) |

## 4. 표시 규칙

- 잰 시각은 한국 시간, 단위는 `%`와 `GB`(1024 기준)입니다.
- 읽는 동안에는 ①이 `확인 불가 (조회 중: …)`로 보이고, 이전 값을 지금 값처럼 보여 주지 않습니다. 기록·막대는 이전에 성공한 조회로 남습니다.
- 비교 줄(`직전 조회와 비교`)은 반올림 전 값으로 계산합니다. 화면에 보이는 반올림된 값의 차이와 0.1쯤 다르게 보일 수 있습니다(예: 42.4%→42.6%인데 `+0.1%p`). 반올림 전 값은 화면에 없어 확인하지 못했고 2일차부터 같은 방식입니다.

## 6. 같은 결과를 다시 만들어 보는 순서

Windows, Node 22~24, 외부 설치(`npm install`) 없음.

1. 저장소를 받고 앱 폴더로 이동합니다.
   ```
   git clone https://github.com/SCA-cloudy/KESHEV-Cloudy.git
   cd KESHEV-Cloudy\on-client
   ```
2. 문법 검사: `npm run check` (오류 없이 끝나야 합니다.)
3. 앱 켜기: `npm start` → 브라우저에서 `http://127.0.0.1:5189`
4. 스크롤하지 않은 첫 화면에서 「학생 상태·알림 표시」 카드의 「내 PC 점검 (내 코드로 조회) · 핵심 3가지」가 보여야 합니다. 누르기 전에는 「PC 값 조회」 버튼과 `아직 조회하지 않음`, ①②③이 `확인 불가` 또는 `아직 성공한 조회가 없습니다`입니다.
5. 「PC 값 조회」를 누릅니다. 눌린 직후에는 「읽는 중…」이 보이고(PC에서 몇 초 걸릴 수 있습니다), 끝나면 버튼이 「다시 조회」로 바뀌고 값과 잰 시각이 나옵니다.
6. 「다시 조회」를 3~5초 간격으로 두 번 더 눌러 ② 기록 3줄, 직전 비교, ③ 막대 3줄을 확인합니다.
7. 연결 실패 화면: 서버 창에서 `Ctrl+C` → `y`로 끄고, 브라우저는 새로고침하지 않은 채 「다시 조회」를 누릅니다. 빨간 상자에 "앱 서버에 연결하지 못했습니다"가 나와야 합니다. 다시 `npm start`로 켜고 「다시 조회」를 누르면 값이 돌아옵니다.
8. 끝내기: 서버 창에서 `Ctrl+C` → `Y`.
9. 가짜 응답 시험(선택): 브라우저에서 `F12` → 콘솔에 짧은 코드를 붙여 조회 요청의 응답을 바꾼 뒤 「다시 조회」를 누릅니다. 앱 파일은 바뀌지 않고 새로고침하면 원래대로 돌아갑니다. 이 방법으로 만든 오류 화면은 서버가 실제로 그렇게 응답한 것이 아닙니다.

## 7. 값이 이상할 때

- 세 항목이 `확인 불가`로 나오면 0이나 정상으로 바뀐 것이 아니라 이번 조회에서 값을 못 읽었다는 뜻입니다. 괄호 안 이유를 봅니다.
- 오류 상자가 나오면 상자 안의 "다음에 할 일"을 순서대로 따릅니다. 가장 흔한 경우(앱 서버를 끈 채로 조회)는 `npm start`를 다시 한 뒤 「다시 조회」를 누르면 됩니다.
