# KESHEV-Cloudy 재현 기록 (22단계)

이 문서는 학생(`student/extension.mjs`를 구현한 사람)이 작성했습니다. 21단계에서 쓴 `docs/STUDENT_RUNBOOK.md`를 대신하지 않고, 그 설명서를 **완전히 새로운 폴더에서 그대로 따라 해본 재현 기록**을 남기는 문서입니다. `README.md`와 `docs/` 아래 다른 제공 문서는 고치지 않았습니다.

이 문서에 적은 "확인함"은 전부 아래 네 가지 중 하나로 표시합니다. 이 구분은 공식 과제 안내의 "시연과 학생 진술 구분" 요구에 따른 것입니다.

| 표시 | 뜻 |
|---|---|
| **[원문]** | 코드·문서 글을 읽고 비교만 한 것. 실행하지 않았습니다. |
| **[모의]** | 가짜(mock) 데이터를 넣어서 함수 결과만 점검한 것. 실제 서버·브라우저를 쓰지 않았습니다. |
| **[시연]** | 예제(demo) 모드처럼 고정된 샘플 자료로 화면을 띄워본 것. 실제 운영 데이터나 실제 연결이 아닙니다. |
| **[실행]** | 학생(저)이 PowerShell/cmd에서 직접 명령을 치고, 브라우저로 직접 들어가서 눈으로 확인한 것. |

AI(이 세션)가 코드 원문만 읽고 "맞다/틀리다"를 판정하는 것은 이 네 가지 중 **[원문]** 에 해당하며, 그것만으로 "실행에 성공했다"고 적지 않습니다.

- Node.js: `v24.21.0` (`node --version`으로 직접 확인). `package.json`의 `engines.node`는 `24.19.0`이지만, 메이저 버전 `24`는 `tools/start-alekov.ps1`이 허용하는 범위(22~24)에 들어가며, 실제로 경고 없이 정상 실행됐습니다.
- 작업 폴더: 기존에 쓰던 작업 폴더와 **별도의 새 빈 폴더**를 만들어 그 안에 `git clone`으로 처음부터 받았습니다(기존 폴더를 복사하지 않음).

## 5. 데이터 보존 계획

- 학생 코드(`student/extension.mjs`)는 `localStorage`·파일 저장·데이터베이스 쓰기를 전혀 하지 않는 **순수 표시 함수**입니다(직접 `grep`으로 확인: 저장 관련 코드 없음). 그래서 이 프로젝트에는 "학생이 쌓은 영구 데이터"가 존재하지 않습니다.
- 보존해야 할 대상은 사실상 **Git 커밋 기록 자체**입니다. GitHub(`origin/main`)가 이미 원격 백업 역할을 하고 있고, 복원 절차는 `git clone` 또는 `git pull` 한 번이면 됩니다(이 문서의 2·3절에서 직접 해본 절차와 동일).
- 브라우저 화면(배지, 표시된 기록 등)은 새로고침하거나 서버를 재시작하면 사라지는 **일시적 상태**이며, 별도 백업 대상이 아닙니다.
- 제한: 서버 쪽 실제 운영 데이터(SDP 호스트의 실제 접속 기록, 실제 설치 패키지 목록 등)에 대한 보존·백업 절차는 이 과제 범위 밖이며, 이 문서는 그 부분을 다루지 않습니다.

## 6. 버전과 지원 범위

- 확인한 조합: Windows + Node `v24.21.0` + 이 저장소의 `9f3381a` 커밋 — 새 폴더에 클론한 뒤 설치 단계 없이 기본/예제 두 모드 모두 실행·종료·재실행까지 성공([실행]/[시연]).
- `package.json`에 적힌 공식 지원 버전은 `24.19.0`이며, 메이저 버전이 같은 `24.21.0`에서는 경고 없이 정상 동작했습니다(`start-alekov.ps1`의 버전 검사 로직과 일치).
- 미해결·미확인 사항(이 문서 작성 시점 기준, 21단계 문서와 동일):
  - 비-Windows 환경에서 `start-alekov.ps1` 없이 실행하는 전체 경로.
  - 실제 SDP 호스트 연결, 실제 AI 모델 연결 성공(ok) 경로, 보안 조치 실집행(19단계 실제 집행) — 전부 담당자가 별도로 구성해야 하며 이 재현 환경에는 없습니다.
  - `ON_APPROVED_PUBLIC_PACKAGES`를 채웠을 때의 실제 취약점 조회 결과(`complete`/`partial`).
- 이 문서의 모든 "확인함" 표시는 AI(서버의 원문 판정)가 아니라 **학생이 직접 실행하거나 모의 데이터로 점검한 결과**이며, 22단계의 통과는 "원문 검토 기준 수료"일 뿐 실제 운영 인증이나 v1.0 자동 인증이 아닙니다(공식 과제 안내 문구 그대로).
