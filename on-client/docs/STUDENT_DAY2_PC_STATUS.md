# 2일차 기록: 내 PC 상태 (STUDENT_DAY2_PC_STATUS)

이 문서는 학생(`student/extension.mjs`를 구현한 사람)이 작성했습니다. `README.md`와 `docs/` 아래의 제공 문서는 고치지 않았습니다. 마무리 과제(마지막 총공세) 2일차 "내 PC의 CPU·메모리·디스크를 실제로 재서 보여 줍니다"를 어떻게 했는지, 무엇이 제공 부분이고 무엇이 내가 바꾼 부분인지, 무엇을 어떻게 확인했는지 적습니다.

확인 표시는 `docs/STUDENT_REPRODUCTION_LOG.md`와 같은 기준을 씁니다.

| 표시 | 뜻 |
|---|---|
| **[원문]** | 코드·문서 글을 읽고 비교만 한 것. 실행하지 않았습니다. |
| **[모의]** | 가짜(mock) 응답을 넣어 화면 결과만 점검한 것. 실제 PC 값이 아닙니다. |
| **[실행]** | 학생(저)이 내 Windows PC에서 직접 명령을 치고 브라우저·작업 관리자로 눈으로 확인한 것. |
| **[AI 작업 공간]** | AI가 자기 작업 공간(리눅스 컨테이너)에서 진짜 앱 서버로 돌려 본 것. 내 PC가 아니므로 참고만 하고 확인함으로 세지 않습니다. |

## 2. 제공 부분과 내가 바꾼 부분

| 구분 | 무엇 | 어디 |
|---|---|---|
| 제공 | 내 PC 값을 실제로 재는 코드(CPU 200ms 표본 1회, 메모리 사용량, 앱이 있는 드라이브의 디스크 여유, 방화벽·Windows 기록 조회) | `src/pc-status.mjs` |
| 제공 | 읽기 전용 조회 주소 `GET /api/pc/status` | `src/server.mjs` |
| 제공 | 위쪽 「내 PC 상태」 카드, 「내 PC 확인」 버튼, "10초마다 확인" 체크박스 | `public/pc-status-view.mjs`, `public/index.html` |
| 제공 | 학생 코드가 `api.get('/api/pc/status')`를 부를 수 있게 허용하고 `createStudentView({ api, onChange })`로 넘겨 주는 것 | `public/app.js` |
| **내가 바꿈** | 「내 PC 점검 (내 코드로 조회)」 구역: 버튼, 상태 구분, CPU 사용률·메모리 사용량·디스크 남은 공간 표시, 최근 5번 조회 기록과 직전 대비 변화 | `student/extension.mjs` |

내가 하지 않은 것:
- CPU·메모리·디스크를 다시 재는 코드를 만들지 않았습니다. 제공 조회 결과를 받아서 보여 주기만 합니다.
- 방화벽·Windows 기록·네트워크는 내 구역에서 다루지 않았습니다(위쪽 제공 카드에서 봅니다).
- 자동으로 반복 조회하지 않고, `fetch`나 새 서버 주소·서버 코드·브라우저 저장소를 쓰지 않았습니다.
- 제공 파일(`public/`, `src/`, 기존 `docs/`)은 직접 고치지 않았습니다. 업데이트 도구가 새 판으로 교체한 것은 제 수정이 아닙니다.

## 3. 고른 개선 한 가지: 최근 조회 비교(추이)

- 무엇을: 「PC 값 조회」를 누를 때마다 CPU·메모리 사용률·디스크 여유를 최근 5번까지 쌓아 두고, 바로 앞 조회와의 차이(`+0.3%p`, `-0.2%p`, `±0.0 GB`)를 보여 줍니다.
- 왜: 제공 카드는 "지금 값 한 번"만 보여 줍니다. 값이 변하고 있는지는 눌러 보며 비교해야 알 수 있어서 이 부분을 내가 더했습니다. 작전 브리핑에서 고른 관제 대시보드형(위 상태, 아래 추이와 기록)과도 맞습니다.
- 한계: 기록은 이 화면의 메모리에만 있어서 새로고침하면 사라집니다(화면에도 적어 두었습니다). 일정한 간격의 그래프가 아니라 내가 누른 시점의 값입니다.

## 4. 표시 규칙

- 잰 시각은 한국 시간으로 같이 보여 줍니다. 단위는 `%`와 `GB`(1024 기준, Windows가 쓰는 방식)입니다.
- 읽지 못한 항목은 0이나 예시 값 대신 `확인 불가 (이유)`로 보여 줍니다. 이유는 권한 부족, 조회 실패, 시간 초과, 응답에 값이 없음 등입니다.
- 조회 결과는 조회 성공 / 오래됨(측정 시각이 60초보다 오래됨) / 실패 / 지원 없음(`NOT_ALLOWED`) / 확인 불가(응답 모양 이상)로 나눠 따로 보여 줍니다.
- 이 칸은 관찰한 값만 보여 주고 정상·안전 판정을 하지 않습니다.

## 6. 같은 결과를 다시 만들어 보는 순서

Windows, Node 22~24, 외부 설치(`npm install`) 없음.

1. 저장소를 받고 앱 폴더로 이동합니다.
   ```
   git clone https://github.com/SCA-cloudy/KESHEV-Cloudy.git
   cd KESHEV-Cloudy\on-client
   ```
2. 문법 검사: `npm run check` (오류 없이 끝나야 합니다.)
3. 앱 켜기: `npm start` → 브라우저에서 `http://127.0.0.1:5189`
4. 위쪽 제공 카드 「내 PC 상태」의 「내 PC 확인」을 눌러 제공 값을 봅니다(내 코드가 아닙니다).
5. 아래로 내려가 「학생 상태·알림 표시」 안의 「내 PC 점검 (내 코드로 조회)」을 찾습니다. 누르기 전에는 "아직 조회하지 않음"입니다.
6. 「PC 값 조회」를 3~5초 간격으로 3번 누릅니다. 기록이 3줄 쌓이고 `직전 조회와 비교` 줄이 나와야 합니다.
7. 작업 관리자(`Ctrl+Shift+Esc` → 성능)를 같이 띄워 메모리·디스크 값을 비교합니다. CPU는 순간값이라 같지 않아도 됩니다.
8. 끝내기: 서버 창에서 `Ctrl+C` → `Y`.

## 7. 값이 이상할 때

- 값이 계속 같다는 이유만으로 예시 값이라고 판단하지 않습니다. 이 값의 출처는 `src/pc-status.mjs`의 `createPcStatusReader`(CPU는 `os.cpus()` 200ms 표본, 메모리는 `os.totalmem()/freemem()`, 디스크는 `statfs`)이고, 서버 경로는 `src/server.mjs`의 `/api/pc/status`입니다. 내 코드에서 이 값을 받는 곳은 `student/extension.mjs`의 `probePc`와 `pcClassify`입니다.
- 일부 항목이 `확인 불가`로 나오면 0이나 정상으로 바뀐 것이 아니라 못 읽었다는 뜻입니다. 이유 문구를 봅니다.
- `지원 없음`이 나오면 내 앱 폴더가 0.2.21이 아닌 이전 판일 수 있습니다. `package.json`의 `version`을 확인합니다.
