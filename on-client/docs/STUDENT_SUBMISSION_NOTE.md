## 3. 제공 부분과 내가 한 것, 겹치는 부분

- 제공: 값을 실제로 재는 코드(`src/pc-status.mjs`), 조회 주소 `GET /api/pc/status`(`src/server.mjs`), 위쪽 카드 「내 PC 상태」와 「내 PC 확인」 버튼(`public/pc-status-view.mjs`), 화면 틀과 모든 CSS.
- 내가 바꾼 파일: `student/extension.mjs` 하나. 제공 파일은 고치지 않았습니다. `student/appearance.json`은 4일차 보정에서 삭제했습니다.
- 제공 카드와 겹치는 것을 줄였습니다. 값을 다시 재거나 CPU·메모리·디스크 현재 값을 다시 그리지 않고, 제공 조회 주소의 결과를 받아 "변화·기록"만 계산합니다.
- 그래도 겹치는 것은 숨기지 않습니다. (1) 「연결과 기록」의 네트워크·방화벽·Windows 경고·오류는 3일차 요청문이 직접 보여 달라고 한 항목이지만 제공 카드에도 같은 정보가 있어 화면에 한 번 더 나옵니다. (2) 「PC 값 조회」 버튼은 제공 「내 PC 확인」 버튼과 같은 조회 주소를 읽는 별개 버튼입니다. 제공 코드가 읽은 값을 학생 코드로 넘겨주지 않아서([원문]) 변화·기록용 값을 얻으려고 따로 두었습니다.
- 자동 반복 조회, `fetch`, 새 서버 주소, 서버 코드 변경, 브라우저 저장소, `innerHTML`은 쓰지 않았습니다([원문]).

## 4. 실제 값과 예시 값의 구분

- 이 칸의 모든 숫자는 제공 조회 주소가 이 PC에서 읽은 값이며 예시 값은 없습니다(칸 안에도 적음). 값 줄마다 잰 시각(한국 시간)과 `[실제 측정]` 표시가 있고, 단위는 `%`, `%p`(차이), `GB`(1024 기준, Windows가 쓰는 방식)입니다.
- 못 읽은 값은 0이나 `정상`으로 꾸미지 않고 `확인 불가 (이유)`로 보여 줍니다. 이유는 권한 부족, 조회 실패, 시간 초과, 이 PC에서는 지원하지 않음, 응답에 값이 없음 등입니다. 정상·안전 판정은 하지 않습니다.
- 예제(demo) 모드(`npm run demo`)에서는 기기·세션·알림이 예제 자료입니다. 그때는 칸 안에 "아래 기기·세션·알림은 예제(demo) 데이터이며 이 PC의 실제 값이 아닙니다"라는 안내가 붙고, 맨 위 배지에도 `예제 데이터(demo) · 실제 연결 아님`이 나옵니다. 이 안내 문구는 코드로 읽어 확인했고 내 PC에서 화면으로 보지는 않았습니다(미확인).
- 이 문서의 숫자 중 `[실행]`이 붙은 것만 내 PC에서 잰 값입니다. 문서 안의 가짜 응답 결과는 `[모의]`로 따로 적었습니다.

## 5. 조회가 실패했을 때

예시 값을 대신 보여 주지 않습니다. 서버를 끄고 「다시 조회」를 누르면 이렇게 나옵니다(캡처로 확인 [실행], 2026-11-03 최종 코드. 2026-11-02에는 중간 코드로 같은 화면을 확인).

- 빨간 상자: 제목 `앱 서버에 연결하지 못했습니다`, 무엇이 안 됐나(오류 코드 `NETWORK_ERROR`, 7개 항목 모두 읽지 못함), 다음에 할 일 3단계
- 이전에 성공한 기록이 있으면 "아래 최근 기록은 이전에 성공한 조회입니다. 이번 값이 아닙니다."
- ① 카드 네 개는 모두 `확인 불가 (앱 서버에 연결하지 못했습니다)`. 「연결과 기록」은 `확인 불가 (조회 실패: …)`
- 서버를 다시 켜고 「다시 조회」를 누르면 값이 돌아오고, 실패한 조회는 기록에 남지 않습니다 [실행].

오류 종류는 서버에 연결 못 함, 시간 초과, 읽을 수 없는 응답, 서버 오류, 응답 모양 이상, 이 앱 판이 허용하지 않음, 측정 시각이 60초보다 오래됨의 7가지이고 각각 제목·다음에 할 일이 따로 있습니다. 서버를 직접 끄는 것으로 만든 것은 연결 실패뿐이고, 나머지는 가짜 응답 [모의] 또는 이전 파일 기준입니다(각 일차 문서 참고).

## 6. 키보드로 쓰기

마우스 없이 `Tab`으로 「PC 값 조회」 버튼에 포커스가 가면 테두리가 보이고, `Enter`로 조회됩니다. 조회 뒤 버튼이 「다시 조회」로 바뀌고 화면이 다시 그려져도 포커스가 버튼에 남아 있어 그대로 다시 누를 수 있습니다. 캡처로 확인했습니다 [실행, 2026-11-02, 6일차 중간 코드. 최종 코드로는 다시 하지 않음]. 어떤 키를 눌렀는지는 캡처에 보이지 않고 학생(저)의 설명에 따랐습니다.

## 8. 같은 결과를 다시 만들어 보는 순서

Windows, Node 22~24, 외부 설치(`npm install`) 없음. 포장 명령은 실행하지 않습니다.

1. 저장소를 받고 앱 폴더로 이동합니다.
   ```
   git clone https://github.com/SCA-cloudy/KESHEV-Cloudy.git
   cd KESHEV-Cloudy\on-client
   ```
2. 파일 확인(선택): `git hash-object student/extension.mjs`가 위 0절의 blob 값과 같은지 봅니다.
3. 문법 검사: `npm run check` (오류 없이 끝나야 합니다.)
4. 앱 켜기: `npm start` → 브라우저에서 `http://127.0.0.1:5189`. `연결 없음`과 빨간 안내는 정상입니다(회사 시스템에 연결하지 않은 상태).
5. 맨 위 제공 카드 4개(내 PC 상태, 현재 로그인, 내 기기, 내 세션)와 그 아래 「학생 상태·알림 표시」 칸을 확인합니다. 조회 전에는 ①이 `확인 불가 (아직 조회하지 않음)`이어야 합니다.
6. 「PC 값 조회」를 한 번, 이어서 「다시 조회」를 몇 초 간격으로 두세 번 누릅니다. 두 번째 조회부터 ① `직전 대비`와 ② `직전 조회와 비교`가 나오고, 보이는 두 숫자의 차이와 같아야 합니다.
7. 키보드(선택): `Tab`으로 「PC 값 조회」에 테두리를 두고 `Enter`로 조회합니다.
8. 실패 화면(선택): 서버 창에서 `Ctrl+C` → `y`로 끄고, 브라우저는 새로고침하지 않은 채 「다시 조회」를 누릅니다. 위 5절처럼 나와야 합니다. 다시 `npm start`로 켜고 「다시 조회」를 누르면 돌아옵니다.
9. 끝내기: 서버 창에서 `Ctrl+C` → `y`.

PowerShell에서 `npm`이 "스크립트를 실행할 수 없습니다"(`npm.ps1`, PSSecurityException)로 막히면 `npm.cmd start`, `npm.cmd run check`처럼 `npm.cmd`로 입력합니다. 실행 정책 설정은 바꾸지 않아도 됩니다. CMD에서는 `npm`을 그대로 씁니다. PowerShell에서는 `cd /d` 대신 `cd "경로"`를 씁니다.

## 10. 미확인과 한계

- 실제 SDP 연결: 실제 연결에는 `--sdp-host-config`와 개인 인증 파일이 필요한데 이 PC에서는 쓰지 않았습니다. 기본 실행은 `연결 없음`이고 22단계는 이 상태로 통과했습니다. 로그인·기기·세션·보안 기록·알림이 실제 연결에서 어떻게 보이는지는 확인하지 못했습니다. 이 PC의 「내 PC」 값(CPU·메모리·디스크·방화벽·네트워크·Windows 기록)은 연결과 상관없이 읽힙니다.
- 틀 해석: 위 1절의 한계. 포털이 "맨 위 상태 카드 네 개"를 제공 카드로 보는지 내 카드로 보는지는 확인하지 못했습니다.
- 확인하지 않은 것: 기준 코드로 읽는 중 화면, 예제(demo) 모드, 항목 하나만 못 읽은 화면(내 PC에서는 모두 읽혀서 가짜 응답으로만 [모의]), 측정 시각이 60초보다 오래되거나 미래인 화면(가짜 응답으로만 확인), 알림 목록이 배열이 아닌 화면, 최종 코드의 키보드 조작, 작업 관리자와의 값 대조, Node 22·23, 다른 PC, 인터넷이 끊긴 상태, 좁은 창.
- 표기 선택과 이전 단계 한계: 단위는 GB로 적었지만 1024 기준(GiB)입니다. 변화는 화면에 보이는 값끼리 빼므로 실제로 0.1%p보다 작게 변해도 `±0.0%p`로 보일 수 있습니다. 알림 안에 비어 있는(`null`) 항목이 있을 때와 필터 `전체` 처리는 이전 단계(13~22단계) 코드의 한계로 이번에 고치지 않았습니다. 알림 목록이 배열이 아닌 경우는 이번에 고쳤지만 실행해 보지 못했습니다.
- 디스크 여유 값은 사용자가 가상머신 파일을 정리하면서 중간에 바뀌었습니다(학생 진술). 앱 오류가 아닙니다.
- 하나의 예외: 작업 중 예제 모드 안내 문구 한 줄을 파일 목록을 보여 주고 확인을 받기 전에 먼저 고쳤고, 이후 방향을 확인받고 이어갔습니다.
- 포털의 AI 검토 기능으로 2·3·4일차를 검토했습니다(최종 코드 직전 파일과 문서로). 검토에서 반복해 나온 지적 중 직접 확인해 맞는 3건을 고쳤습니다(7절 7~9). 그 결과는 참고로만 썼고, 코드나 문서와 직접 확인해 맞는 지적만 고쳤습니다. 검토 결과 자체가 통과·실패를 뜻하지는 않습니다.
